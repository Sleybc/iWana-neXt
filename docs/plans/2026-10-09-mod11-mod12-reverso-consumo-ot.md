### Evidencia necesaria para G7

- **G6.5:** **GO** en `91c1f5e93f0ccb862ec08963bc60008bfe1d22d9`: CI [`38070902801`](https://github.com/Sleybc/iWana-neXt/actions/runs/38070902801) pasó todos los gates bloqueantes (lint/typecheck/build/unit tests, imágenes, R4.1 e integridad ADR); smoke web [`38070902780`](https://github.com/Sleybc/iWana-neXt/actions/runs/38070902780) pasó. El conteo E2E portal es informativo y seguía en curso. La corrida anterior `38069910178` falló porque la aserción de foco observaba el diálogo antes del `requestAnimationFrame`; la corrección espera el foco y el spec local pasó 51/51. `26a6c8b5` había fallado al descargar Google Fonts; se cambiaron las dos apps a fuentes locales con sus licencias.
- **V5-R:** **cerrado** por `sec-eng`, GO de lectura independiente en [`INFORME-MOD11-MOD12-REVERSO-V5-SEC-ENG-v1.2.md`](../informes/INFORME-MOD11-MOD12-REVERSO-V5-SEC-ENG-v1.2.md).
- **Recomendación de staging:** reutilizar el proveedor/host Linux que ya opere la plataforma si existe; si no existe, habilitar un host dedicado no productivo con Docker Compose, API y worker de la misma imagen por digest, PostgreSQL de prueba, Redis con contraseña y MinIO dedicado. Mantener un tenant y credenciales sintéticos en el secret store, acceso privado y datos aislados. No usar producción. El repositorio no revela proveedor ni host al que desplegar, así que no se puede fijar un destino ni medir hasta que el responsable de infraestructura indique dónde aprovisionarlo.
- **p95/p99 compartido (R2):** medir desde que `queue.add` resuelve hasta que el worker real deja el asset fuera de `QUARANTINED`, con Redis y MinIO accesibles por sus endpoints del staging. El gate aprobado por el CTO es **p95 ≤ 1,5 s**; p99 se informa como diagnóstico. La medición local fue p95 62,4 ms secuencial, 167,9 ms en ráfaga de 10 y p99 máximo 192,4 ms; no representa un entorno compartido. Si el p95 supera 1,5 s, R2 pide recalibrar `retryDelaysMs` y repetir. Para correr la misma muestra se necesitan API/worker y DB de prueba, Redis con contraseña y MinIO dedicados, un tenant sintético, y acceso por secret store a `REDIS_HOST/PORT/PASSWORD/DB` y `S3_ENDPOINT/BUCKET/ACCESS_KEY_ID/SECRET_ACCESS_KEY`. Protocolo y medición local: [`INFORME-MOD11-CONSOLA-OT-OLA2B-R2-FE-PLATFORM-v1.0.md`](../informes/INFORME-MOD11-CONSOLA-OT-OLA2B-R2-FE-PLATFORM-v1.0.md) §4 y [`r2-p95-analisis-evidencia.json`](../quality/mod11-ola2b/r2-p95-analisis-evidencia.json).
- **Monitoreo del worker:** el heartbeat solo se renueva cuando cada proveedor `WorkerHost` descubierto tiene el worker en ejecución, sin pausa, y su cliente BullMQ conectado (`status=ready`). Si falla alguna condición, se borra la clave y `dist/worker-healthcheck.js` declara unhealthy. Las pruebas locales cubren 169/169; el probe de Docker demostró `healthy → unhealthy → healthy` ante `SIGSTOP`/`SIGCONT`. Recomendación de alerta: notificar si `worker-prod` permanece `unhealthy` durante 60 s y cerrar la alerta al recuperar; mantener una señal/alerta separada para Redis. El repo no configura el recolector ni el destino de notificación, por lo que esta condición requiere acceso a la plataforma operativa.
