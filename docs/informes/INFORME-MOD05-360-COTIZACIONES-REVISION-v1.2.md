## RED → GREEN de R7 y comprobación HTTP

La primera prueba de lectura R7, con PostgreSQL real y la entidad hidratada por TypeORM, detectó que `birth_date` se serializaba como `1990-05-01T00:00:00.000Z` en lugar de `1990-05-01`. La corrección serializa el valor como fecha solo-día en UTC cuando TypeORM entrega un `Date`, y conserva el texto cuando entrega `YYYY-MM-DD`. La integración R7 pasó después con 1 suite y 1 test.

La primera comprobación HTTP de desarrollo de R8 encontró además un fallo en escritura: al enviar `1990-05-01`, el detalle y la ficha 360° devolvieron `1990-04-30`. R7 agregó pruebas de servicio para create y update; antes de corregir la asignación a la columna `date`, fallaron 2/2 al detectar que se guardaba un objeto `Date`. R7 preservó el texto de entrada (o `null`) en ambas operaciones. La suite de servicio resultante pasó 88 tests y la integración de lectura R7 pasó 1/1.

Tras ese cambio se creó un segundo suscriptor sintético en la API de desarrollo. Los GET de detalle y 360° devolvieron exactamente `1990-05-01`, igual a la fecha enviada. El DELETE lógico respondió 200. El token de acceso y los valores de autenticación permanecieron en memoria durante la prueba y no aparecen en este informe.
