## 3. Prueba de forma `{ age }`

Caso no-inventario del spec (`execution-order-relay.service.spec.ts:76,108-112`):

```ts
(['ExecutionOrderStartedV1', { age: 30 * 24 * 60 * 60 }],
  // ...
  expect(eventsQueue.add).toHaveBeenCalledWith(
    'deliver-execution-event',
    expect.any(Object),
    expect.objectContaining({ removeOnFail: expectedRetention }),
  ));
```

- La firma del `it.each` es `[string, { age: number }]`; pasar `2592000` como número es error de tipo y, en runtime, `objectContaining({ removeOnFail: { age: 2592000 } })` no iguala a `removeOnFail: 2592000` (BullMQ 5.71 interpreta el número como cantidad de jobs, no como edad). La prueba falla ante un número y pasa solo con la forma `{ age }`.
- Los tres tipos de reverso están en `INVENTORY_OUTBOX_EVENT_TYPES` y tienen caso propio con `{ age: 86400 }`; sin esa inclusión caerían en la rama de 30 días.
- Búsqueda en código productivo: ningún `removeOnFail` numérico restante (solo `{ age: … }`, `false` intencional o `true`); ningún `removeOnComplete` numérico. Verificado con `removeOnFail:\s*[^{\sfalse]` (solo coincide la línea ternaria del relay + docs históricas).
